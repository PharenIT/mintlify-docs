---
title: "TLS and reverse proxies"
sidebarTitle: "TLS & proxy"
description: "Expose Pharen safely with bundled TLS or an explicitly trusted external proxy."
---

Remote installations require HTTPS. Before a certificate exists, public HTTP serves only `/healthz` and ACME challenges. Application HTTP is enabled only when `PHAREN_PUBLIC_URL` is loopback.

Set `LETSENCRYPT_EMAIL`, point DNS to the host, allow TCP 80/443, then run:

```bash
./pharen tls
```

The bundled proxy returns 404 for `/admin/` and for raw protected `/media/` paths. It exposes only avatars, team icons/backgrounds, workspace logos, and agent avatars directly; protected files are downloaded through authenticated APIs.

For an external proxy, firewall the Pharen host so only the proxy can reach it, set `PHAREN_EXTERNAL_PROXY_MODE=true`, and set `PHAREN_EXTERNAL_PROXY_CIDRS` to only that proxy's container or host CIDRs. The bundled proxy validates this list, trusts `X-Forwarded-For` and `X-Forwarded-Proto` only from those sources, and replaces all forwarding headers before Django. The mode permits firewall-restricted HTTP between the proxies; the public proxy must provide HTTPS. Preserve WebSocket upgrades for `/ws/`, `/webrtc/`, and `/kb-ws/`.
